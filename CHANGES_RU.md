# Что изменено в надёжной версии

## Критические исправления

- Исправлено создание SQLite-схемы с нуля.
- Удалена зависимость от старых таблиц `shift_assignments`, `reports`, `audit_logs`.
- Оставлена единая модель: `shifts` + `shift_members` + `shift_reports`.
- Добавлены транзакции `BEGIN IMMEDIATE` и rollback для критических операций.
- Защищено последнее место на смене от одновременного захвата двумя пользователями.
- Защищены выплаты от двойного списания доступного остатка.
- Защищены approve/reject отчётов и инвайтов от двойной обработки.
- Исправлен отчёт смены: `принято всего`, `на особняке`, `самостоятельно` хранятся отдельно и валидируются.
- Многоместная смена больше не завершается целиком после отчёта первого участника.
- Нельзя одновременно запустить вторую активную смену.
- Исправлены команды с modal: нет `defer()` перед `send_modal()` в одном interaction.
- Исправлена статистика: нет обращений к несуществующим `total_points` и `shift_members.created_at`.

## База данных

- WAL, foreign keys, busy timeout.
- Транзакционный слой с единым lock на SQLite-соединение.
- Индексы под реальные запросы.
- CHECK-ограничения для статусов, числовых полей, отчётов и финансов.
- Миграция существующей старой БД.
- Автоматический предмиграционный backup перед переходом на актуальную schema v3.
- `PRAGMA user_version=3`.
- Создание timestamp-триггеров для старых непустых таблиц, где SQLite не может безопасно добавить `DEFAULT CURRENT_TIMESTAMP` через `ALTER TABLE`.

## Финансы

- `finances` используется как главный журнал операций.
- `users.total_salary` / `paid_salary` считаются кешем и могут быть сверены/исправлены.
- `/финансы сверить`.
- Максимальная сумма одной операции задаётся `MAX_FINANCE_AMOUNT`.
- Суммы нормализуются до 2 знаков.
- Выплата больше доступного остатка блокируется внутри транзакции.

## Уведомления и фоновые задачи

- Фоновые loops реально запускаются и корректно отменяются.
- Уведомление сначала резервируется в БД, потом отправляется.
- Есть статусы `pending/sent/failed`, счётчик попыток и retry зависшего `pending`.
- Недельный отчёт имеет защиту от дублей и catch-up после простоя.
- Ошибки loops логируются с traceback.

## Discord UI

- ID объекта встроен в `custom_id` кнопок.
- Кнопки новых сообщений не зависят от старого Python View после рестарта.
- Для смен хранится `message_id`; обновление идёт напрямую по сообщению.
- Есть резервные команды approve/reject по ID отчёта и инвайта.
- Добавлена `/смена исправить` для повторной отправки отклонённого отчёта.
- Help полностью синхронизирован с новой логикой.

## Диагностика и эксплуатация

- `/админ здоровье` проверяет:
  - SQLite quick_check;
  - foreign keys;
  - целостность смен/участников/отчётов;
  - корректность финансовых операций и остатков;
  - сверку финансового кеша;
  - сервер, каналы и роли;
  - состояние фоновых loops.
- `/админ бэкап` использует SQLite Backup API.
- Логи идут в консоль и ротируемый `bot.log`.
- Startup fail-fast: неверный config или не загрузившийся обязательный Cog не маскируется.

## Удалить из старой папки

Не переносить в новую версию:

- `logging.py`
- `notifications.py`
- `weekly_stats.py`

Они относятся к старой архитектуре и намеренно отсутствуют в готовом проекте.

## Проверки

Перед упаковкой выполнено:

```bash
python -m compileall -q .
pytest -q
```

Первоначальный набор был расширен; финальный результат: **39 тестов пройдено, 3 полных прогона подряд**.

Проверяются в том числе:

- чистая схема SQLite;
- CHECK/UNIQUE constraints;
- полный цикл смены;
- reject → исправление → approve отчёта;
- reject → повторная отправка → approve инвайта;
- конкурентный захват последнего места;
- конкурентная двойная выплата;
- запрет второй активной смены;
- миграция старой непустой базы;
- автоматический предмиграционный backup;
- retry notification reservation.

## Исправления после приёмочного теста

- Исправлена отправка ЛС рекрутеру после принятия/отклонения инвайта: modal теперь использует `inter.bot`, а не несуществующий `self.bot`.
- При создании новой смены бот пингует роль рекрутеров. Поведение можно отключить через `PING_RECRUITERS_ON_SHIFT_CREATE=false`.

## Админ-панель `/база`
- Добавлен новый Cog `cogs/database_admin.py` и сервис `services/database_service.py`.
- `/база пользователь @user` открывает интерактивную карточку с обзором и кнопками: финансы, смены, отчёты, инвайты, логи, изменение статика, добавление заметки, обновление обзора.
- `/база найти запрос` ищет по Discord ID, статику или части username.
- `/база статик` безопасно меняет профильный статик и обновляет только текущие booked/active смены; исторические завершённые записи не переписываются.
- `/база заметка` добавляет служебную заметку с аудитом.
- `/база финоперация id` показывает конкретную запись финансового журнала без возможности опасного ручного редактирования денег.
- Все изменения статика/заметок выполняются транзакционно и пишутся в `logs`.

## Панель управления кнопками

- Добавлена постоянная панель Recruiter Bot с кнопками для рекрутеров, старшего состава и администраторов.
- Панель автоматически создаётся/обновляется после запуска и пытается закрепиться в канале.
- По умолчанию используется канал смен; можно задать `PANEL_CHANNEL_ID`.
- Рекрутеру доступны кнопки: начать/завершить/выйти со смены, расписание, исправление отчёта, профиль, статистика, финансы, цели, инвайты.
- Создание нового инвайта теперь возможно полностью через интерфейс: выбор пользователя → статик/имя → чек-лист.
- Старшему составу доступны создание смены, список инвайтов на проверке и общие финансы.
- Администратору доступны время, диагностика уведомлений, бэкап и быстрая проверка.
- Slash-команды сохранены как резервный способ управления.

## 2026-08-25 — максимальный логический аудит / schema v3

- Схема БД поднята до `PRAGMA user_version=3`; перед миграцией старой рабочей БД создаётся `.pre_v3_...db`.
- В `shift_reports` и `invites` добавлен `message_id`: новые карточки синхронизируются напрямую, история канала используется только для legacy fallback.
- Добавлен отдельный `health_service`: единая диагностика для slash-команды и кнопочной админ-панели.
- `/админ здоровье` теперь проверяет schema version, целостность статусов, лимиты свободных мест, Discord permissions, дубликаты статиков, финансовые аномалии и фоновые loops.
- Исправлена логика многоместной активной смены: ранний старт одного участника не отнимает запись у остальных до официального начала.
- В момент официального старта кнопка записи закрывается; самостоятельный выход после начала недоступен.
- Самостоятельно вышедший рекрутер может вернуться; снятый старшим — нет.
- Исправлены смены через полночь и границы расписания в 00:00.
- Пустые закончившиеся смены автоматически финализируются.
- Частично отработанное время снятого участника не попадает в завершённые часы статистики.
- Профильный статик защищён от случайной перезаписи опечаткой; дубликаты статиков блокируются.
- Добавлены единые лимиты длины статика, длительности смены и количества мест.
- Нельзя создать смену в прошлом, инвайт на себя/бота или второй активный инвайт на того же Discord-пользователя.
- Чек-лист инвайта показывает сохранённый выбор и блокирует создание при противоречивом состоянии.
- Финансовые модальные окна поддерживают десятичную запятую; суммы округляются до 2 знаков единообразно.
- Недельные финансы исправлены: сравнение `created_at` идёт по UTC-границам соответствующей локальной недели.
- Начисления/выплаты через интерфейс Recruiter Bot защищены от случайного выбора постороннего участника сервера.
- Цели вынесены в транзакционный `goal_service`, добавлена валидация типа/периода/значения и единая операция удаления.
- Кнопочная панель приведена к функциональному паритету с рабочими slash-командами; просмотр профиля другого рекрутера остаётся доступен обычному рекрутеру, как и slash-вариант.
- Логи `bot.log` форматируются в `TIMEZONE` бота.
- В зависимости добавлен `tzdata`, чтобы `Europe/Moscow` стабильно работал на Windows и slim-контейнерах.
- Расширены сценарные тесты: миграция v2→v3 с сохранением строк, цели, границы суток, русская десятичная запятая, message_id, повторная запись/снятие и другие бизнес-инварианты.
- Исправлено отображение SQLite `created_at`: системные UTC-времена логов, финансов и инвайтов теперь показываются пользователю в `TIMEZONE` бота, поэтому в Discord больше не должно быть скрытого смещения на 3 часа.

# Установка исправления Recruiter Bot v6.1 через GitHub и BotHost

Это исправление работающей v6. Схема БД остаётся 6; рекруты, смены, рекламы,
статистика, цели и все существующие настройки сохраняются.
Архив не содержит рабочую базу, токен или .env. Скрипты для установки не нужны.

## Что исправлено

В v6 отложенный ответ на кнопку выбирал режим обновления исходного сообщения.
Поэтому «Реклама» могла заменить общую панель, а личный результат записи —
попасть на карточку смены. v6.1 создаёт отдельный ответ, видимый только нажавшему.
Публичная карточка по-прежнему обновляет состав смены при успешной записи.

Проверки доступа обычного рекрута к руководству, админке и чужой проверке
проходят. Права проверяются при взаимодействии, в том числе после снятия роли
и при отправке ранее открытой формы. Новых возможностей или правил нет.

## Пошаговая установка

1. В Discord нажмите «Админ → Бэкап», скачайте свежую копию базы. Сохраните
   предыдущий код: GitHub main → Code → Download ZIP.
2. Остановите существующего бота на BotHost.
3. Распакуйте recruiter_bot_v6_1_hotfix.zip в отдельную папку. Внутри папки
   recruiter_bot_v6_1_hotfix находятся cogs, tests и файлы в корне.
4. На GitHub откройте репозиторий Aleksey1235/recruiter-bot. В переключателе
   веток выберите main. Создайте от неё ветку codex/recruiter-v6-1-private-ui.
5. В корне этой новой ветки нажмите Add file → Upload files. Перетащите ВСЁ
   СОДЕРЖИМОЕ папки recruiter_bot_v6_1_hotfix: папки cogs, tests и остальные
   файлы. Не перетаскивайте сам ZIP или внешнюю папку recruiter_bot_v6_1_hotfix.
   В поле загрузки должны быть cogs/advertising.py, cogs/panel.py,
   cogs/shifts.py и tests/test_interaction_privacy.py с правильными путями.
   В cogs архива только три изменённых файла; остальные файлы этой папки
   в репозитории сохраняются. Ничего вручную удалять не нужно.
6. Нажмите Commit changes в этой ветке. Откройте Compare & pull request:
   base main, compare codex/recruiter-v6-1-private-ui. Создайте pull request,
   затем Merge pull request → Confirm merge.
7. На существующей карточке BotHost выполните обновление кода из Git с
   пересборкой, дождитесь завершения и запустите бота. Обычный перезапуск
   без получения нового кода не устанавливает исправление.
   Переменные окружения, Dockerfile, каталог данных и БД не меняйте.

## Проверка в Discord

1. Общая панель, которую заменило меню рекламы, должна восстановиться при
   запуске на прежнем сообщении. Личные ответы записи убираются с недавних
   карточек смен в пределах последних 200 сообщений канала, если их ID
   совпадает с сохранённой привязкой в БД. Другие сообщения не очищаются.
   Если более старая карточка осталась испорченной, сообщите её номер;
   удалять карточку или смену не нужно.
2. Нажмите «Реклама». Должно появиться личное меню с пометкой «Только вы видите
   это сообщение». Общая панель остаётся на месте со всеми кнопками.
3. Проверьте запись на подходящую смену. Результат виден только нажавшему.
   При успешной записи публичная карточка обновляет состав. При отказе
   личная причина не появляется над публичной карточкой.
4. Под ролью обычного Recruiter нажмите «Руководство» и «Админ»: бот должен
   ответить личным отказом и не открыть защищённые функции. В общем сообщении
   эти кнопки могут быть видны всем — доступ к действию проверяет бот.
5. Обычному Recruiter в личном меню рекламы доступны только собственные
   публикации, статистика и история. Очередь проверки, рейтинг и статистика
   отдела/другого рекрутера доступны Senior/Admin. Обычный Recruiter не должен
   видеть закрытый канал с фото по настройкам разрешений Discord.
6. Нажмите «Админ → Здоровье». Схема БД по-прежнему 6, проверки проходят;
   старые показатели в профиле, сменах и целях сохраняются. Скачайте новый backup.

## Ограничения проверки

236 тестов прошли на Python 3.11.17 с настоящими disnake 2.12.1 и aiosqlite
0.22.1. До исправления воспроизведены 8 сценариев утечки личного ответа в общее
сообщение. HTTP/Gateway Discord и рабочая БД в тестах не использовались.
Изменены только три файла исполняемого интерфейса; остальные изменения —
версия, документация, контрольные суммы и тесты. Полная проверка описана
в VALIDATION_RU.md.

Если сборка или запуск не удались, сохраните лог и остановите бота. Базу
не удаляйте и reset_database.py не запускайте. Исходную версию v4 нельзя
запускать на БД v6; для отката v6.1 сохраните именно предыдущее состояние v6.

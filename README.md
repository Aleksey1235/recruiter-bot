# Recruiter Bot — Full Audit Final

Discord-бот на **Python 3.11 + disnake + SQLite** для отдела Recruiter: смены, отчёты, инвайты, статистика, финансы, цели, служебные заметки, диагностика и резервные копии.

Основной интерфейс — **постоянная кнопочная панель**. Slash-команды сохранены как резервный способ управления.

## Быстрый запуск

```bash
python -m pip install -r requirements.txt
python main.py
```

Обязательные переменные находятся в `.env.example`. Для текущей схемы рекомендуется:

```env
DATABASE_PATH=data/recruiter_bot.db
TIMEZONE=Europe/Moscow
PANEL_CHANNEL_ID=ID_ОТДЕЛЬНОГО_КАНАЛА_ПАНЕЛИ
```

`tzdata` входит в `requirements.txt`, поэтому IANA-таймзона `Europe/Moscow` работает и на системах, где базы часовых поясов нет из коробки.

## Обновление существующего бота без потери данных

1. Сделайте `/админ бэкап` и скачайте файл.
2. Остановите старый бот.
3. **Не удаляйте и не заменяйте** рабочую `data/recruiter_bot.db`.
4. Обновите код из этого архива/GitHub.
5. Сохраните прежние ENV-переменные.
6. Запустите бот.
7. При первом запуске БД версии ниже 3 автоматически получает предмиграционный backup вида `recruiter_bot.db.pre_v3_YYYYMMDD_HHMMSS.db`.
8. Выполните `/админ здоровье`.

Текущая схема: **`PRAGMA user_version=3`**. Миграция v2 → v3 добавляет `message_id` к карточкам отчётов и инвайтов и не удаляет существующие строки.

## Кнопочная панель

### Рекрутер

- Смена: начать, завершить, выйти **до официального начала**, расписание, исправить отклонённый отчёт.
- Профиль: свой и профиль другого действующего рекрутера.
- Статистика: сегодня / неделя / месяц / всё время, рейтинг, неделя по дням.
- Финансы: баланс и последние операции.
- Цели: текущие цели и прогресс.
- Инвайты: новый инвайт полностью через UI и список своих инвайтов.
- Помощь.

### Старший состав

- создать / отменить смену;
- снять рекрутера со смены;
- проверить, одобрить или отклонить отчёт;
- проверить, принять или отклонить инвайт;
- база принятых, поиск по статику, заметки к инвайтам;
- статистика и финансы рекрутера;
- общие финансы;
- постановка, просмотр и удаление целей;
- служебные заметки.

### Администратор

- время и фактический `TIMEZONE`;
- диагностика уведомлений;
- логи;
- консистентный backup SQLite;
- расширенное `/админ здоровье`;
- начисление / выплата / финансовая сверка и исправление кеша;
- безопасная панель БД: карточка пользователя, поиск, статик, заметка, история, финансовая операция.

## Логика смен

`shifts.slots` — текущее число свободных мест. Захват места выполняется атомарно внутри `BEGIN IMMEDIATE`.

Важные правила:

- записаться можно только **до `scheduled_start`**;
- начать свою смену можно не раньше чем за `EARLY_START_MINUTES` до начала;
- если один рекрутер начал многоместную смену раньше времени, остальные всё ещё могут занять свободные места до официального начала;
- после официального начала запись закрывается и карточка показывает `Запись закрыта`;
- самостоятельно выйти можно только из `booked` до официального начала;
- после самостоятельного выхода можно записаться повторно;
- после снятия старшим составом самостоятельно вернуться на эту же смену нельзя;
- завершение одного участника не завершает остальных;
- смены через полночь поддерживаются;
- пустая закончившаяся смена автоматически финализируется;
- один рекрутер не может иметь две пересекающиеся booked/active смены или две active смены одновременно.

## Отчёты смен

Отдельно хранятся:

- принято всего;
- на особняке;
- самостоятельно.

Бот запрещает отрицательные значения и комбинацию, где категории превышают общее число. Отклонённый отчёт можно исправить и отправить повторно. Для новых карточек сохраняется `message_id`; поиск по истории нужен только как fallback для старых сообщений.

## Инвайты

Кнопочный сценарий:

`Новый инвайт → пользователь Discord → статик/имя → чек-лист → Создать отчёт`.

После выбора чек-лист остаётся видимым с `✅/⬜`; кнопка создания заблокирована до корректного выбора. `Ничего из списка` нельзя совместить с другими пунктами.

Защиты:

- нельзя создать инвайт на себя или бота;
- статик уникален;
- один Discord-пользователь не может одновременно иметь несколько pending/accepted инвайтов;
- отклонённый инвайт может повторно отправить тот же рекрутер;
- карточка инвайта хранит `message_id`.

## Финансы

Таблица `finances` — источник истины. `users.total_salary` и `users.paid_salary` — кеш, который проверяет `/финансы сверить` и `/админ здоровье`.

- суммы нормализуются до копеек;
- поддерживается ввод с десятичной запятой в модальных окнах;
- нельзя выплатить больше доступного остатка;
- критические операции транзакционные;
- начисления/выплаты в интерфейсе Recruiter Bot ограничены действующими рекрутерами/старшим составом;
- недельный отчёт считает только операции соответствующей локальной недели, переводя границы в UTC для `created_at`.

## Уведомления

Таблица `notifications` хранит `pending / sent / failed`, число попыток и последнюю ошибку. Резервирование атомарное, поэтому повторные циклы не должны дублировать уже отправленное уведомление.

Фоновые задачи:

- 30- и 10-минутные напоминания;
- предупреждение об опоздании;
- отметка пропуска;
- напоминание завершить активную смену;
- напоминание senior о pending-отчётах;
- контроль подозрительно короткой смены;
- недельный отчёт с catch-up после простоя;
- ежедневный консистентный backup в канал логов.

## Диагностика

`/админ здоровье` проверяет:

- доступность SQLite и `PRAGMA quick_check`;
- foreign keys;
- schema version;
- целостность статусов смен/участников/отчётов;
- аномальные свободные места;
- дубликаты статиков;
- финансовый журнал, отрицательные остатки и кеш;
- сервер, каналы и необходимые Discord permissions;
- роли;
- работу фоновых loops.

`/админ время` показывает `TIMEZONE`, локальное время бота, UTC и путь к БД. Логи `bot.log` также форматируются в настроенной таймзоне.

## Защита данных

Критические бизнес-операции находятся в `services/` и используют транзакции `BEGIN IMMEDIATE` с rollback. Условные `UPDATE ... WHERE status=...` + проверка `rowcount` защищают approve/reject, последнее место и выплаты от повторной обработки.

`.gitignore` и `.dockerignore` исключают `.env`, SQLite-файлы, WAL/SHM, логи и кеши Python. **Никогда не загружайте токен или рабочую БД в публичный GitHub.**

## Тестирование этой сборки

Локальный аудит включает:

```bash
python -m compileall -q .
python -m pytest -q
```

Сервисные тесты работают на реальном SQLite через тестовый async-адаптер и покрывают миграции, транзакции, гонки, смены, отчёты, инвайты, финансы, статистику, цели и граничные сценарии. Статические контракты отдельно контролируют архитектуру и кнопочную панель.

Важно: в среде сборки нет подключённого Discord Gateway, поэтому финальная проверка живых Discord interactions делается smoke-test'ом после загрузки на хост.
